Troubleshooting guide

The major fear with all data storage applications is database corruption. Although extensive methods are in place to prevent this from occuring, regular backups of database are encouraged and are performed by clicking the button below. Also, a lot of stuff has to work perfectly for the data logging system to work. This guide is here to help you identify and rectify any errors that may occur.

Perform database backup

1. When an error is encountered, the first thing to do is to try the action again. This is because the logging system has automatic features that attempt to identify and rectify any errors. These self-rectifying methods will take up to 1 minute.

2. If the error still persists, check your network connection to the master unit. Do this by attempting to load up a new webpage from the data-logging website.

3. If the network connection is ok, the next thing to do is to check the error log. Scroll to the bottom to find out a brief description of the error. If the error indicates bad connections to certain slave units, check the physical connections between the master and slave unit.

View error log

4. If the error is still unresolved, it's possible the master unit may somehow of corrupted its internal running state. Manually turn off and on the master unit.

5. If error still persists, is is likely that the internal database structure on the master unit has become corrupted. The only way to recover from this is to perform a restore of a previous working version of the database. Download all obtainable data from the logger and then restore the loggers internal database backup.

Restore internal backup

6. In the unfortunate case that you've reached this stage, your data logging system is seriously fucked. The only option now is to download all obtainable data from the logger and then restore it to factory default settings.

Reset to factory settings

7. If your error is still unresolved, please contact our technical team at ECH Engineering.
